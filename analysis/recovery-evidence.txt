## What the script may use (measured out of the capture, Nov 20)

`/sbin/busybox` carries `awk cat cut date echo expr grep head md5sum mkdir mount reboot sed sha1sum sleep stat
sync tail touch umount`; it does **not** carry `dd wc cp rm ls tr sha256sum`. The ramdisk also ships `/system/bin`
(toybox plus real binaries: `sha256sum dd tr rm wc cp ls blockdev devmem sh`) together with `/system/bin/linker64`
(1,445,568 B) and `/system/lib64` (`libc.so`, `libdl.so`, `libc++.so`), so those run before recovery mounts the
system slice. The script resolves every tool to `/system/bin/<name>` when present and to the busybox applet
otherwise; partition reads use `cat`, sizes use `stat -c %s`, the raw RAM read uses `tail -c +N | head -c`,
nothing is deleted (the request is retired by a nonce-named done-marker), and only `reboot echo sleep sync date`
are called on busybox directly.

## Offline logic gate - `scripts/smoke_recovery_evidence.sh`, rc 0, nine scenarios

1. run outside the unit - guard refuses (rc 1), nothing written, no mount attempted, no reboot;
2. no restore request - `/cache` mounted before the evidence directory is created, records copied, partition 7
   untouched, rebooted so the record becomes readable over adb;
3. request staged, partition 7 differs - rollback written through `cat`, digest verified, `restore-ok.txt`,
   done-marker named after the nonce, request file kept (busybox has no `rm`);
4. the same nonce cannot re-arm the restore;
5. partition 7 already on the rollback image - skipped, not written;
6. request with no rollback staged - partition 7 untouched, the reason recorded;
7. no digest tool anywhere - restores **anyway** and writes `restore-unverified.txt`, never claiming a match
   (two empty digests compare equal, which is the defect this scenario guards);
8. an install package on a card - the restore still runs, recovery is left alone, no reboot (**D80**'s condition);
9. pstore not a filesystem - the raw RAM read lands at the ramoops offset and the printable view comes from
   `/system/bin/tr`.

What it does not prove: the shell dialect. busybox ash is not on this workstation, so POSIX syntax is checked here
with `bash --posix -n` and still has to be checked with `dash -n` and `busybox ash -n` on the build host before
partition 8 is written again.
