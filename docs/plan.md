# Plan — Android 14 (LineageOS 21) on a PX6 / HCT4 unit with the shipped vendor + kernel

Decisions locked (see `docs/decisions.md`): target **Android 14**, base **LineageOS 21**,
kernel = **shipped 4.19 binary first, rebuild from BSP source later**, vendor = **blobs untouched +
wrappers**, apps = **keep HCT4 apps for v1**, security = **pragmatic during bring-up, strict at
release**, delivery = **Update.zip on USB/SD** with the unit's existing upgrade flow.

## Architecture of the ROM

We do **not** rebuild `vendor`. The build produces new `system` / `product` / `odm` (+ APEXes) and a
new `boot.img` (old 4.19 kernel binary + Lineage 21 first-stage ramdisk + second stage). The shipped
`vendor.img`, `uboot.img`, `trust.img`, `dtbo.img`, `RKLoader.bin` and `/data` are left untouched.
Everything Android 14 needs that the old vendor lacks is added **in our own partitions**:

| Needs Android 14 | Where it goes |
|---|---|
| KeyMint (`IKeyMintDevice`) | built from AOSP source, installed into our vendor-overlay partition or as a system-side service; declared in the device manifest we ship |
| `libhardware_legacy`, hwc2-on1/onfb adapters, `libchrome`, `libion` | vendor-local copies built from Android-10 sources, installed in `/vendor` (a small "shim overlay" written into the existing vendor image, or as an appended `vendor` logical partition we rebuild with the same blobs) |
| device manifest / compatibility matrix | Android 14 versions generated by our device tree |
| SELinux policy | rebuilt from Lineage 21 + our vendor sepolicy additions (Android 10 vendor labels mapped forward) |
| fstab | Android 14 variant pointing at the same block names, keeping F2FS `/data` |
| super layout | rewritten `dynamic_partitions_op_list` (sizes + possibly `vendor_ramdisk`) |

## Milestones

### M1 — facts from the live unit (blocks everything else)
Run `scripts/device_inspect.sh` on the unit (root shell, or via `adb`). Needed output:
`getprop`, `uname`, `/proc/cmdline`, `/proc/partitions`, `blockdev --getsize64 /dev/block/by-name/super`,
`ls /dev/block/by-name/`, `ls /proc/config.gz`, `getenforce`, `ps -Z`, `service list`, vintf files,
MCU version, `/dev/mtc*` permissions, Magisk version. Deliverable: `analysis/device-report.txt`.

### M2 — environment + device tree skeleton
- Workstation: ~120 GB free for the Lineage 21 tree + ~30 GB for build output (we have 518 GB free).
- `repo init` LineageOS 21 (`lineage-21.0`), `repo sync` (hours; ask before starting).
- `device/rockchip/rk3399-px6-hct4/`:
  - `BoardConfig.mk`: dynamic partitions, no AVB (`BOARD_AVB_ENABLE := false`), boot header v2
    (`BOARD_BOOT_HEADER_VERSION := 2`), `TARGET_USES_ION := true`, Mali/EGL props, group sizing.
  - `device.mk`: inherit nothing from Rockchip vendor source; import prebuilt vendor tree
    (`tools/extract_vendor.py` → copies blobs/configs out of the assembled `vendor.img`).
  - `manifest.xml`: Android 14 format, `target-level="4"` (vendor stays Android 10) + KeyMint entry +
    `<kernel target-level=.../>` (or the VINTF kernel-config workaround, see M4).
- Deliverable: tree builds `system.img`/`product.img`/`odm.img` with the old vendor attached.

### M3 — boot test (framework-only flash)
1. Backup: full partition dump + the current `update.zip` (rollback).
2. Build a test zip that only replaces `system`, `product`, `odm` (+ our shims) and `boot.img`.
3. Boot acceptance: `sys.boot_completed=1`, SurfaceFlinger up, `audioserver` up, `keystore2` up,
   HCT apps still usable (radio, AMP/EQ, AV-in, back-view, BT phone, GPS, CarPlay).
   Failure modes to watch: vendor ramdisk missing, libion absent, hwc2 adapter absent, VINTF mismatch.

### M4 — Android 14 vendor-side gaps (the "wrapper" work in `hal/`)
- `libion` shim for `/dev/ion` (kernel 4.19 Rockchip ion) → `gralloc.rk30board.so` / `libgralloc_drm.so`.
- vendor copies of `libhardware_legacy.so`, `libhwc2on1adapter.so`, `libhwc2onfbadapter.so`, `libchrome.so`.
- KeyMint: start with AOSP software implementation (attestation flagged test-only); later wrap
  `keystore.rk30board.so` if hardware-backed keys matter.
- VINTF kernel check: either rebuild kernel with `CONFIG_IKCONFIG_PROC` (M6) or patch
  `libvintf`/`assemble_vintf` in our fork to skip kernel-config matching during bring-up.
- Deliverable: `vendor_shim.img` (or shim files in the zip) + a short smoke-test script per HAL.

### M5 — packaging in the Rockchip Update.zip format
`tools/mk_update_zip.py`:
- brotli-compress partition payloads + generate `*.transfer.list` (blockimgdiff, block size 4096) —
  or simply write raw images with `package_extract_file()` to `/dev/block/by-name/<logical>`;
- `dynamic_partitions_op_list` with the new sizes;
- reuse the shipped custom `update-binary` (it knows `write_raw_loader_image()` / `do_rk_firmware_upgrade()`)
  and a new `updater-script` asserting `ro.product.device == "rk3399"`;
- sign with our own key (`signapk`), keep `RKLoader.bin`/`uboot`/`trust`/`dtbo` byte-identical unless we change them.
- Deliverable: flashable `Update.zip` + `docs/release.md` with rollback steps.

### M6 — kernel rebuild (security upgrade, after a working Android 14)
- Find GPL-published kernel source for this platform (Rockchip BSP 4.19 + the out-of-tree `mtc-*`
  driver; HU vendors are obliged to publish it — ask the unit vendor / Hal9k).
- Rebuild 4.19 with stable/LTS backports, `CONFIG_IKCONFIG_PROC=y`, dm-verity, and keep the MTC driver.
- Re-test graphics/camera/tuner; then drop the VINTF workaround and re-enable enforcing verity.

### M7 — hardening pass (release quality)
- enforcing SELinux, `androidboot.selinux` removed from cmdline;
- dedicated least-privilege SELinux domains for `hctcanbusservice`, tuner/AMP nodes, CarPlay bridges;
- device-node permissions: `/dev/ttyS*` 0600/0660 owners, `/dev/mtc-*` 0660, drop world-writable;
- remove Magisk and the `u:r:shell:s0` root services (`adbec`, `usbmuxd`, `vendingpatch.sh`, `hctlog.sh`);
- ADB disabled by default (only via explicit user toggle), own signed offline updates, no third-party OTA host;
- verify TLS/browser stack: updatable WebView APEX from our build, current security patch level.

### M8 — release engineering
Reproducible build script, changelog, unit-support matrix (which HCT/MTCD variants boot), test report,
and a documented "restore to Hal9k Android 10" procedure.

## Order of work right now

1. M1 device data (needs the unit).
2. M2 environment + tree skeleton (needs your go-ahead for the multi-hour Lineage sync).
3. M3 boot test on a **spare/test unit** if available; otherwise on your unit with a verified rollback.
4. M4 shims, M5 packaging, then M7/M6 as above.
